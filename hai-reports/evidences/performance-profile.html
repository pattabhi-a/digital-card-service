Performance Profile

TL;DR
  • PDF generation is fully synchronous on the WebSub callback thread (controller:88 → service:138 → PDFCardServiceImpl:342).
  • No @EnableCaching, no @Async anywhere in src/main/java (verified via grep).
  • Single thread pool of size 5 for re-subscription scheduling only (DigitalCardApplication.java:29).
  • Helm replicaCount: 1 (helm/digitalcard/values.yaml:27) — no horizontal scale by default.
  • Each generation makes 3+ blocking REST calls (DataShare fetch, decrypt, PDF sign) on the request thread.
