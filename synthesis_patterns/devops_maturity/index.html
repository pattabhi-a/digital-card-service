Practice 1: CI/CD Pipeline Maturity

Current State: 5-stage pipeline (build → test → publish → docker → scan); ~20-35 minutes; GitHub Actions
❌ Current Gaps:
  • No image scanning (Trivy/Snyk); vulnerable dependencies can slip through
  • No Helm chart validation (chart lint only); deployment errors caught only in staging
  • Manual promotion between environments (dev → staging → prod); prone to configuration drift
  • No blue-green deployments; each release risks downtime
  • Rollback is manual (rollback commit → wait for build → deploy)
✅ Improved Pipeline:
  • Add Image Scanning: Trivy scans image for CVEs; fail build if critical vulnerabilities found
  • Add Helm Validation: Helm unittest validates deployment before push to registry
  • Automated Promotion: Tag-based promotion (dev:latest → staging:latest → prod:tagged)
  • Blue-Green Deploy: Deploy new version alongside old; switch router with single command
  • Instant Rollback: Rollback is router switch (seconds, not minutes)

Enhanced Pipeline Architecture

Pipeline Stages: 1. Build (Maven) └─ Compile, unit tests, JAR packaging 2. Test (JUnit + Surefire) └─ Run test suite, generate coverage 3. Publish (Nexus) └─ Publish JAR to Maven Central 4. Docker Build └─ Build image, push to registry 5. Security Scan (Trivy) ← NEW └─ Scan image for vulnerabilities; fail if critical 6. Helm Validation ← NEW └─ Validate chart syntax, template rendering 7. Deploy to Dev (automatic) └─ Deploy dev image to dev cluster 8. Manual Approval └─ Human reviews; approves staging/prod promotion 9. Deploy to Staging (automatic) └─ Deploy staging image to staging cluster 10. E2E Tests (automatic) ← ENHANCED └─ Run integration tests against staging 11. Deploy to Prod (blue-green) ← NEW └─ Deploy prod image alongside current; switch router Total duration: ~25-30 minutes

Blue-Green Deployment Flow

Current State (Production): Blue Pod (v1.2.3) ← Router directs traffic Green Pod (old version, disabled) Deploy v1.3.0: 1. Deploy new Green Pod (v1.3.0) 2. Run smoke tests against Green 3. If tests pass: Switch router Blue → Green 4. Monitor Green for errors (1-5 min) 5. If no errors: Decommission old Blue 6. If errors: Switch back to Blue (instant rollback) Result: Zero-downtime deployment; instant rollback

Timeline: 2 weeks | Cost: $8K

Practice 2: Infrastructure as Code (IaC)

Current State: Helm charts (v1.3.0) + Kubernetes; good foundation
❌ Current Gaps:
  • No PDB (Pod Disruption Budget); rolling updates can cause downtime
  • No NetworkPolicy; unrestricted pod-to-pod communication
  • Security context disabled; pods run as root
  • No Kyverno policies; teams can deploy insecure configurations
  • Manual scaling; no HPA or resource requests validation
✅ Improved IaC:
  • PDB: Ensure ≥1 pod always available during updates
  • NetworkPolicy: Deny-all ingress; allow only required egress (external services)
  • SecurityContext: runAsNonRoot, fsGroup, readOnlyRootFilesystem
  • Kyverno: Enforce policies (require resource limits, no root, require security context)
  • HPA: Auto-scale 3-10 replicas based on CPU

Enhanced Helm Values

Timeline: 1-2 weeks | Cost: $5K

Practice 3: Automated Testing Strategy

Current State: Unit tests + integration tests; ~3-5 min execution
❌ Current Gaps:
  • No e2e (end-to-end) tests; integration broken features only caught in staging
  • No load tests; performance regressions missed
  • No security tests (OWASP); vulnerabilities not caught in pipeline
  • No contract tests; breaking changes between services go undetected
✅ Improved Testing:
  • E2E Tests: Selenium/Playwright tests validate entire user workflows
  • Load Tests: k6/JMeter tests validate P99 latency targets under peak load
  • Security Tests: OWASP ZAP scanner validates against top vulnerabilities
  • Contract Tests: Pact tests ensure API contracts between services
  • Chaos Tests: Resilience tests (kill pods, slow services, inject errors)

Testing Pyramid

▲ /|\ / | \ E2E Tests (5 min, 3% of tests) / | \ - Full credential generation workflow /───┼───\- Selenium/Playwright / | \- Validate UI + backend integration / | \ / | \ Integration Tests (3-5 min, 20% of tests) /───────┼───────\- Database interactions, external service mocks / | \- Spring TestContainers / | \ / | \ Unit Tests (2-3 min, 75% of tests) /____|______|__________ - Business logic only | | - JUnit + Mockito Load Tests (separate, ~10 min): k6 load scenarios Security Tests (separate, ~5 min): OWASP ZAP scanning

Timeline: 3-4 weeks | Cost: $12K

Practice 4: Operational Runbooks & Automation

Current State: Basic logging; on-call relies on tribal knowledge
❌ Current Gaps:
  • No runbooks; on-call engineer searches logs manually (30-60 min MTTR)
  • No auto-remediation; common issues require manual intervention
  • No incident response process; chaos when things break
  • No capacity planning; team surprised by scale challenges
✅ Improved Operations:
  • Runbooks: Automated troubleshooting guides for common issues
  • Auto-Remediation: Alertmanager + webhooks trigger remediation scripts
  • Incident Response: Formal process: Detection → Alerting → Response → Postmortem
  • Capacity Planning: Regular review of metrics; proactive scaling

Example Runbook: High Error Rate

Alert: Error rate >5% for 5 minutes Automatic Response: 1. Check external service health (KeyManager, DataShare) 2. If service is down: - Activate circuit breaker fallback - Notify on-call engineer (PagerDuty) 3. If service is slow: - Increase timeout threshold - Auto-scale pods (HPA will handle) - Notify on-call engineer 4. If local issue: - Check JVM heap usage - If >85%: Trigger graceful pod drain (Istio) - Notify on-call engineer Manual Actions (if auto-remediation fails): 1. SSH to pod: kubectl exec -it pod-name bash 2. Check logs: tail -f /var/log/app.log | grep ERROR 3. Check heap: jcmd PID GC.heap_dump /tmp/dump.hprof 4. Restart pod: kubectl delete pod pod-name

Incident Response Process

Phase Duration Actions
Detection <2 min Alert fires; PagerDuty notifies on-call
Response 2-5 min On-call investigates; checks dashboards; runs runbook
Mitigation 5-15 min Temporary fix (rollback, scale, timeout adjust)
