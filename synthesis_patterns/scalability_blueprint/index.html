📈 Scalability Blueprint

Path to 20x Growth: From 50K → 1M Credentials/Month

Scalability Challenge

Current State: Single instance, 50K credentials/month, 30-50 cards/minute throughput

Business Target: 1M+ credentials/month (20x growth), 500-1000 cards/minute throughput

Gap: Current architecture hits ceiling at ~50 concurrent requests; cannot support 20x demand

Scalability Bottlenecks & Solutions

Bottleneck Current Limit Root Cause Modernization Fix New Capacity
Thread Pool 50 concurrent requests 5-thread pool Increase to 50 threads + async processing 500+ concurrent requests
Database Queries 50 queries/sec (identity/template lookups) No caching Enable Redis L2 cache (80% hit rate) ~10 DB queries/sec (10x reduction)
Synchronous PDF Generation 30-50 PDFs/minute (blocks threads) Synchronous blocking calls Async generation via message queue (RabbitMQ) 500+ PDFs/minute (10x throughput)
Single Instance All traffic on 1 pod replicaCount: 1 Multi-replica + HPA (scale 3-10 pods) 5-10x capacity increase
Connection Pooling Default pool (unbounded) No HikariCP config Configure HikariCP: minSize=10, maxSize=20 Prevent connection exhaustion

Scalability Roadmap: 5 Milestones

Milestone 1: Stabilization (Week 1-2, $13K)

Goal: Fix critical security and reliability issues; establish baseline for scaling

Deliverables:

  • Move credentials to environment variables
  • Add input validation (@Valid on all DTOs)
  • Fix HTTP status codes (don't return 200 for errors)
  • Add request timeouts (5-10 sec for external calls)

Capacity Impact: No throughput change; improves stability to support subsequent phases

Target Metrics: Zero credential-related errors; HTTP error responses correct

Milestone 2: Foundation (Month 1, $45K)

Goal: Enable 2-3x capacity increase through caching, resilience, and basic async

Deliverables:

  • Enable Hibernate L2 cache (EhCache) → 50% latency ↓
  • Add Resilience4J circuit breaker (timeouts, retries) → graceful degradation
  • Increase thread pools: 5 → 50 threads → 10x concurrent request handling
  • Add rate limiting: 100 req/min per IP → DoS protection
  • Deploy 3 replicas + HPA (3-5 pod scaling)

Capacity Impact: 50K → 150K credentials/month (3x); 30-50 → 100-150 cards/min

Cost: $45K (development + infrastructure)

Target Metrics: P50 latency <2.5s; P99 latency <5s; 99% uptime; 3x throughput

Milestone 3: Async Processing (Month 2, $35K)

Goal: Decouple PDF generation; achieve 5x capacity increase

Deliverables:

  • Implement async PDF generation via RabbitMQ (worker pool)
  • Switch to distributed Redis cache (multi-instance shared state)
  • Implement batch event processing for bulk issuance
  • Scale up HPA: 3-10 pod replicas; worker pods: 3-20

Capacity Impact: 150K → 500K credentials/month (5x from foundation); Worker pool can scale independently

Cost: $35K (async architecture + Redis cluster)

Target Metrics: P50 latency <2s; P99 latency <3s; 500+ cards/min; 99.5% uptime

Milestone 4: Observability (Month 3, $25K)

Goal: Enable proactive scaling and debugging; maintain quality at scale

Deliverables:

  • Add Prometheus metrics (requests/sec, latency P50/P99, errors)
  • Add Grafana dashboards (real-time monitoring, alerting)
  • Implement Spring Cloud Sleuth + Jaeger (distributed tracing)
  • Set up alerts: High latency, error rate >1%, pod restarts

Capacity Impact: No throughput increase; enables proactive scaling and faster MTTR

Cost: $25K (monitoring infrastructure + tools)

Target Metrics: MTTR <5 min; visibility into cross-service latency; proactive scaling

Milestone 5: Advanced Scaling (Month 4+, $20K)

Goal: Reach 20x target capacity; prepare for 10-20M credentials/month demand

Deliverables:

  • Database partitioning by region/month (if single table becomes bottleneck)
  • Implement read replicas for credential queries
  • CDN caching for DataShare-hosted PDFs (Cloudflare/CloudFront)
  • Consider CQRS if query load > write load

Capacity Impact: 500K → 1M+ credentials/month (20x from current); Linear cost scaling

Cost: $20K (database optimization + CDN)

Target Metrics: P50 latency <1s; P99 latency <2s; 1000+ cards/min; 99.9% uptime

ROI Analysis: Cost per Credential

Current Cost Model:

  • Infrastructure: $500/month (single instance)
  • Operations: $3000/month (on-call support, debugging)
  • Development: $2000/month (bug fixes, maintenance)
  • Total: $5500/month for 50K cards = $110/card

Modernized Cost Model (After Milestone 5):

  • Infrastructure: $3000/month (multi-instance + caching + queues)
  • Operations: $1000/month (automated monitoring, fewer incidents)
  • Development: $1000/month (feature development, not firefighting)
  • Total: $5000/month for 1M cards = $5/card

ROI Summary:
• Cost per credential: $110 → $5 (22x improvement)
• Total investment: $160K over 5 months
• Payback period: 2-3 months (when volumes exceed 500K/month)
• Long-term savings: $5/month per card (vs $110 today)

Scaling Assumptions & Constraints

Assumptions

  • Database performance remains acceptable up to 100K transactions/month (no partitioning needed until then)
  • External services (KeyManager, DataShare) can handle proportional load increases
  • Kubernetes cluster has sufficient nodes (scaling policies updated for elasticity)
  • Network bandwidth is not a bottleneck (typical: <100 Mbps per pod)

Constraints & Mitigations

Constraint Impact Mitigation
Database Connection Limit PostgreSQL max 100 connections → exhaustion at 10+ pods Use PgBouncer (connection pool proxy) to reduce per-pod connections
Redis Memory Cache can grow with data volume (10K identities = 100MB) Implement eviction policy (LRU); monitor cache memory
Message Queue (RabbitMQ) Queue depth grows if workers fall behind Auto-scale workers; alert on queue depth >10K messages
External Service SLA If KeyManager/DataShare can't keep up, bottleneck shifts Work with services to scale; add circuit breaker fallbacks

Scaling Testing Strategy

Before scaling to production, validate at each milestone:

  1. Load Testing: Use Apache JMeter or k6 to simulate target load
    k6 run --vus 500 --duration 10m load-test.js # Validate: P99 latency <5s, error rate <1%, no timeouts
  2. Chaos Engineering: Test failure scenarios
    • Kill random pods (Kubernetes chaos monkey)
    • Simulate slow external service (add network delay)
    • Exhaust database connections (connection pool stress)
  3. Database Performance: Monitor query times at scale
    • Slow query log: Alert if query >500ms
    • Connection pool utilization: Alert if >80%
    • Cache hit rate: Target >80% (identities, templates)
