🎨 Architecture Patterns

✅ Layered 3-Tier Architecture
Clear separation: Controller → Service → Repository → Database. Good separation of concerns; each layer has single responsibility.
✅ Event-Driven via WebSub
Services communicate asynchronously via pub/sub. Reduces coupling; enables independent scaling; handles peak loads gracefully.
✅ Service Interface Pattern
Service interfaces (DigitalCardService, CardGeneratorService) with implementations. Promotes loose coupling; easy to mock in tests.
✅ Repository Pattern with JPA
Data access abstracted via repositories. Enables easy database switching; consistent query interface.
✅ Centralized Exception Handling
@RestControllerAdvice catches all exceptions; returns consistent error format. Reduces boilerplate; better error UX.
✅ Dependency Injection (Spring)
Constructor and field injection throughout. Enables loose coupling; easy testing; clear dependencies.

🚨 Critical Issues

CRITICAL: Exception Swallowing in Event Handlers P0

DigitalCardController catches exceptions in WebSub callbacks and only logs errors without retry.

catch (Exception e) { logger.error("credential request initiation is failed."); // No retry mechanism; no dead-letter queue }

Impact: Failed credential requests silently fail; no visibility; data loss.

Fix: Implement retry logic with exponential backoff or dead-letter queue for failed events.

CRITICAL: Missing Null Safety in Event Handlers P0

Direct method chaining without null checks before calling toString().

eventModel.getEvent().getData().get("registration_id").toString() // NPE if registration_id key missing or value is null

Impact: NullPointerException on malformed events; service crashes.

Fix: Add defensive null checks; use Optional; validate event structure on entry.

CRITICAL: Broad Generic Exception Catching P0

Multiple catch(Exception e) blocks without specific exception handling.

catch (Exception e) { logger.error("operation failed"); // Loses exception context }

Impact: Difficult debugging; loses stack traces; hides root causes.

Fix: Catch specific exception types (IOException, JsonProcessingException, etc.).

CRITICAL: Hardcoded Magic Strings P0

Event data keys scattered throughout code as magic strings.

"registration_id", "id_hash", "credential", "credentialType", "protectionKey" // No constants defined; fragile to API changes

Impact: Fragile to API changes; difficult refactoring; inconsistent naming.

Fix: Define all event keys as constants in DigitalCardConstants.

HIGH: Large Service Class (SRP Violation) P1

DigitalCardServiceImpl - 323 lines with multiple responsibilities:

  • Credential request initiation
  • Card generation coordination
  • Database transaction management
  • WebSub publishing

Impact: Hard to test; hard to understand; violates Single Responsibility Principle.

Fix: Extract credential initiation and WebSub publishing to separate services.

HIGH: Duplicate Event Handler Logic P1

Event handling logic repeated 3 times for identity create, identity update, and credential events.

Impact: Maintenance burden; inconsistent error handling; DRY violation.

Fix: Extract common logic to private helper method; parameterize by event type.

👃 Additional Code Smells & Anti-Patterns

RestClient Generic Method Complexity P2

Generic method with 7 parameters; manual URI building; hard to use correctly.

Recommendation: Create specific methods for different endpoint types (getToken, createCard, etc.).

Unchecked Type Casting P2

RestClient returns generic <T> but casts without verification.

Recommendation: Use ObjectMapper.convertValue() with type safety; add validation.

Missing @Valid on Controller DTOs P3

RequestBody accepted without validation annotations.

Recommendation: Add @Valid and implement JSR-303 constraint annotations (@NotNull, @NotBlank, etc.).

Hardcoded Scheduling Configuration P3

Fixed delay for re-subscription; already configurable but could be more flexible.

Recommendation: Implement exponential backoff instead of fixed delay.
