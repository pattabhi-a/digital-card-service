🚀 Digital Card Service - Deployment Architecture

Containerization, Orchestration & CI/CD Pipeline

📦 Containerization

✅ Modern Java Base Image
Uses OpenJDK 21 JRE (mosipid/openjdk-21-jre:21.0.4). Latest Java version with modern features.
⚠️ Single-Stage Dockerfile
No multi-stage build. All dependencies included in single layer; larger image size (~800MB+).
⚠️ Dynamic Artifact Downloads
Downloads PDF generator and auth adapter at runtime from Artifactory. Network dependency; potential supply chain risk.

JVM Configuration

  • GC: ZGC with generational mode (modern, low-latency)
  • Heap: Min 1.25GB, Max 2.25GB (aggressive sizing)
  • Diagnostics: HeapDumpOnOutOfMemoryError enabled
  • String Dedup: Enabled (reduces memory)

⚠️ Single Replica (replicaCount: 1)
No high availability; single point of failure. Recommendation: Deploy 3-5 replicas in production.
⚠️ No Horizontal Pod Autoscaler
Manual scaling only; can't respond to load spikes automatically.
⚠️ No NetworkPolicy
Pod-to-pod communication unrestricted. Recommendation: Implement deny-all + allow rules.
⚠️ Security Context Disabled
Container runs as root. Recommendation: Add securityContext with runAsNonRoot, fsGroup.

Health Probes

  • StartupProbe: 30s interval, 10 failures (aggressive startup detection)
  • LivenessProbe: 120s initial, 10s interval (validates running state)
  • ReadinessProbe: 60s initial, 10s interval (ready to accept traffic)
  • Endpoint: /v1/digitalcard/actuator/health

🔄 CI/CD Pipeline

GitHub Actions Workflow: push-trigger.yml

Stage Tool Description Duration
1. Build Maven Compile, unit tests, package JAR 5-10 min
2. Test JUnit, Surefire Run test suite; generate coverage 3-5 min
3. Publish Nexus (OSSRH) Publish JAR to Maven Central 2-3 min
4. Docker Build Docker CLI Build image; push to registry 5-10 min
5. Code Quality SonarQube Static analysis; coverage reporting 2-3 min

Total Pipeline Duration: ~20-35 minutes

✅ Multi-Stage Pipeline
Build → Test → Publish → Docker → Scan. Logical progression with clear gates.
✅ Automated Image Build
Docker images automatically built and pushed on release/tag events.
✅ SonarQube Integration
Code quality metrics collected; trend analysis.
⚠️ No Image Scanning
Docker images not scanned for vulnerabilities. Recommendation: Add Trivy or Snyk scanning.
⚠️ No Helm Chart Validation
Chart linted but not tested. Recommendation: Add Helm unittest or Kube-score validation.

💾 Database

✅ PostgreSQL 14+
Modern, reliable database; proper UTF-8 encoding; optimized driver.
✅ Schema Versioning
Database migration scripts tracked; upgrade path defined.
⚠️ Single Table Design
All transaction data in digitalcard_transaction table. May hit performance limits with millions of records.
⚠️ No Partitioning
Recommendation: Partition by date or region if volume grows.

Database Configuration

  • Owner: postgres
  • Template: template0 (clean state)
  • Encoding: UTF8
  • Connections: No explicit pooling config (recommend HikariCP with maxPoolSize=20)
