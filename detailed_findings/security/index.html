🔒 Digital Card Service - Security Analysis

Threats, Vulnerabilities & Risk Assessment

🚨 Critical Vulnerabilities

CRITICAL: Credentials Stored in Plain Text

Database password `4YbeUrM2bD` visible in application.properties files.

Risk: Unauthorized database access; data breach; compliance violation.

Fix: Use environment variables, HashiCorp Vault, or AWS Secrets Manager.

CRITICAL: All Errors Return HTTP 200 Status

ApiExceptionHandler returns HTTP 200 even for 403 Forbidden, 500 Internal Server Error.

Risk: Violates HTTP standards; masks failures; breaks client error handling.

Fix: Return appropriate status codes (400, 403, 500, etc.).

CRITICAL: Missing Input Validation

Controller endpoints accept parameters without @Valid, null checks, or type validation.

Risk: Injection attacks; NullPointerException; unexpected behavior.

Fix: Add @Valid on DTOs; implement JSR-303 constraints.

CRITICAL: Sensitive Data in Logs

Stack traces include credentials; database credentials logged as strings.

Risk: Credential exposure via log aggregation; compliance violation (PII protection).

Fix: Implement log masking; exclude sensitive fields from logs.

CRITICAL: No Rate Limiting

No protection against API abuse or distributed denial-of-service attacks.

Risk: Service disruption; resource exhaustion; business impact.

Fix: Implement rate limiting via Spring Cloud Gateway or @RateLimiter.

⚠️ Security Findings

HIGH: No Request Timeout Configuration

RestTemplate calls to external services have no timeout; requests may hang indefinitely.

Fix: Configure connectTimeout and readTimeout (recommend 5-10 seconds).

HIGH: No Circuit Breaker Pattern

If KeyManager, DataShare, or Credential Service are unavailable, service will fail.

Fix: Implement Resilience4J circuit breaker for external calls.

HIGH: WebSub Secret in Configuration

Secret value `test` in properties; should be externalized.

Fix: Move to environment variables or vault.

MEDIUM: Reflection-Based Field Access

Utility.java uses Java reflection; potential security/performance risk.

Fix: Replace with type-safe alternatives; limit reflection scope.

MEDIUM: No Distributed Tracing

No request correlation IDs; difficult to trace requests across services.

Fix: Add Spring Cloud Sleuth + Jaeger for distributed tracing.

✅ Security Strengths

Encryption Integration
Proper integration with KeyManager for encrypting/decrypting sensitive data. Cards encrypted before DataShare upload.
WebSub Authentication
Event webhooks validated using HMAC-SHA256 signature verification. Only legitimate events processed.
PII Protection
UINs stored as salted hash; no plaintext personal data in database.
Audit Trail
All card generation events logged with timestamp, user, status.
Spring Security Integration
Keycloak authentication enabled; JWT token validation on all endpoints.

🛡️ Recommended Security Roadmap

Immediate (Week 1)

  • Move credentials to environment variables or vault
  • Add input validation with @Valid on all DTOs
  • Implement request timeout configuration (5-10 sec)
  • Add log masking for sensitive fields

Short-term (Week 2-3)

  • Implement rate limiting via Spring Cloud Gateway
  • Fix HTTP status codes (return 400/403/500 appropriately)
  • Add circuit breaker for external service calls
  • Implement distributed tracing (Sleuth + Jaeger)

Medium-term (Month 1-2)

  • Add API key/OAuth2 client credentials for service-to-service calls
  • Implement Web Application Firewall (WAF) rules
  • Add security headers (CORS, CSP, etc.)
  • Conduct penetration testing
